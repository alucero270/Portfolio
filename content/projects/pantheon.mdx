## Overview

Pantheon is the self-hosted engineering infrastructure behind Loose Arrow Labs. It runs a full local AI stack, VLAN-segmented lab network, centralized storage, and documentation-driven operational procedures — designed for reproducibility, security, and recovery rather than hobbyist experimentation.

The infrastructure serves as both a working production environment and a proof of the documentation-driven methodology applied to real systems.

## AI Stack

The AI stack runs on Prometheus, a dedicated Ubuntu compute system with an RTX 4000 Ada GPU. Operational services:

- **llama-swap** — model router with alias-based selection across backends; primary voice and chat inference host
- **Ollama** — secondary model hosting and OpenAI-compatible API
- **llama.cpp** — direct inference for lower-overhead serving
- **OpenWebUI** — primary human-facing interface for chat, model testing, and admin
- **ComfyUI** — image generation workflow
- **SearXNG** — local search for AI-assisted retrieval

### Voice Agent

A local real-time voice conversation loop validated and tuned on Prometheus:

- **STT**: Whisper large-v3-turbo via a unified Python voice API server
- **LLM**: llama-swap routing to Granite 4.1 8B GPU
- **TTS**: Qwen3-TTS 1.7B with hybrid triton/faster-qwen3-tts backend
- **Transport**: Pipecat 1.2.1 with SmallWebRTC

**Measured latency after optimization:**

| Path                     | Latency                                                |
| ------------------------ | ------------------------------------------------------ |
| Qwen3-TTS stock baseline | 8–10 seconds per short response                        |
| Hybrid backend (triton)  | 0.38s short / 1.07s sentence / 2.67s 105-char response |

Key constraint: Qwen3-TTS and large GPU models cannot coexist on the RTX 4000 Ada. Granite 4.1 8B fits alongside Qwen3-TTS and is the validated production candidate.

## Network Architecture

- **Zero-trust-lite model**: no VLAN trusted by default; inter-VLAN traffic explicitly allowed only when required
- **Cerberus**: enforces all firewall policy at the network edge
- **Atlas**: Unraid NAS as the authoritative storage system — all authoritative data lives here
- **Prometheus**: disposable compute; rebuildable; AI and service workloads run here
- **Remote access**: Tailscale baseline for validated remote paths

## Documentation-Driven Operations

Every system has architecture docs, procedures, runbooks, and recovery guides. Architecture decisions are captured as ADRs with explicit rationale, consequences, and alternatives considered.

Current decision records: zero-trust-lite network model, Atlas as authoritative storage, disposable compute model for Prometheus, centralized ingress, llama-swap backend selection.

The automation model is documentation-first: documentation defines intended state, Ansible configures safe host targets after validation, Pulumi C# handles future API-backed infrastructure. Nothing is automated that is not documented.

## Engineering Problem

A technical studio needs infrastructure that supports real work without becoming fragile:

- Services must be reproducible and documented
- Networks must separate concerns and reduce accidental coupling
- Storage must be deliberate and recoverable
- AI workloads need compute boundaries and operating notes
- Failures must produce logs and troubleshooting paths, not guesswork
